# DTC NEXIS — المتطلبات الإلزامية لفهرس السيارات وربط أكواد الأعطال

**التاريخ:** 2026-11-18  
**الحالة:** SPECIFICATION / REVIEW ONLY، دون استيراد بيانات أو تغيير البرنامج أو قناة التحديث.
**نطاق هذه الوثيقة:** كل ماركات وموديلات السيارات التي يمكن توثيقها من مصادر موثوقة ومرخصة. لا تعني توفّر جميع الحقول لكل سيارة.

## 1 — قواعد لا يمكن تجاوزها
1. **لا يساوي اسم الموديل هوية المركبة الفنية.** سنة الطراز والسوق/البلد والجيل والمحرك وناقل الحركة والوحدة الإلكترونية تغير نطاق الانطباق.
2. يُحفظ لكل سجل **مصدر قابل للتتبع** وإصدار المصدر وتاريخ المراجعة والترخيص وحدود السوق ودرجة الثقة. يَظل غير المعلوم `null` ولا يُخمن.
3. لا يُستخدم ربط DTC إلا بقرينة تقنية موثوقة تثبت انطباقه على السيارة والمحرك ووحدة ECU؛ وإلا يُسجّل `needs_review` في قائمة مراجعة منفصلة.
4. تُحفظ جميع اختلافات المصنع الصحيحة، ولا يُحذف سجل مصدّق بسبب التشابه النصي. المقارنة تكون بالهوية الفنية ونطاق التطبيق والمصدر.
5. الصور الجديدة متوقفة، والوسائط السابقة لا تُمس؛ لا نسخ لبيانات مرخصة بشكل غير متوافق ولا تعديل RC3.8.0/RC3.8.2.

## 2 — حقول هوية السيارة الأساسية (أساسية عند توافر المصدر)
| المجموعة | الحقول | التفسير |
|---|---|---|
| الهوية | `make`, `make_aliases`, `model`, `model_aliases` | الاسم القياسي والبدائل |
| التصنيف | `vehicle_kind`, `body_type`, `platform` | سيارة ركاب/فان/شاحنة…، نوع الهيكل والمنصة إذا ثبت |
| الحقبة | `model_year_start`, `model_year_end`, `generation`, `generation_year_start`, `generation_year_end`, `model_year` | تمييز سنة الطراز عن بداية/نهاية الإنتاج/التسجيل |
| السوق | `market_country`, `region`, `steering_side`, `regulatory_variant` | لا تفترض تساوي الأسواق |
| تعريفات خارجية | `source_vehicle_id`, `external_ids`, `former_ids` | الربط مع مصادر الفهرس دون تغيير المعنى |
| نسخة السيارة | `trim`, `variant_label`, `factory_type_code` | عندما يتوافر إثبات |
| محرك | `engine_code_oem`, `engine_family`, `fuel_type`, `displacement_cc`, `cylinders`, `power_kw`, `torque_nm`, `emissions_standard` | كود المحرك المصنعي لا يُستنتج من الحجم/القوة |
| كهربائي/هجين | `powertrain_type`, `motor_code_oem`, `battery_chemistry`, `battery_capacity_kwh`, `hv_architecture` | عند توثيقها، لا تعميم على كل نسخة |
| ناقل الحركة | `transmission_type`, `transmission_code_oem`, `gear_count`, `transmission_model`, `transmission_manufacturer` | لا يُستنتج كود علبة السرعة من وصف CVT/AT/MT |
| الدفع | `drivetrain`, `drive_system_variant` | FWD/RWD/AWD/4WD وتفصيل النظام الموثق |
| تاريخ المصدر | `source_url`, `source_id`, `source_version`, `license`, `attribution`, `source_checked_at`, `source_record_hash` | شرط لتتبع كل معلومة |
| جودة السجل | `field_evidence`, `confidence`, `status`, `review_reason` | لكل حقل غير مؤكد، توثيق عدم اليقين |

## 3 — تعريف وحدات التشخيص وربط أكواد DTC (طبقة مستقلة)
- `ecu_system`: ECM/PCM، TCM، ABS/ESP، SRS، BCM، HVAC، Steering، Immobilizer، Network/CAN، EV/BMS وغيرها.
- `ecu_manufacturer`, `ecu_model`, `ecu_part_number`, `ecu_software_version`, `protocol`: لا تُملأ إلا بمصدر صريح.
- `dtc_code`, `dtc_subcode`, `manufacturer_definition`, `symptoms`, `probable_causes`, `diagnostic_procedure`, `repair_guidance`, `references`, `applicability`.
- `applicability` تحفظ قيود **الجيل/سنوات الطراز/السوق/كود المحرك/كود ناقل الحركة/ECU/البرنامج**؛ قد تكون غير معروفة، وعندها لا يُعتمد الربط التلقائي.
- يُمنع توليد أو استنتاج معنى DTC من معرّفات وظائف الصيانة أو المعلومات العامة عن السيارة.

## 4 — مطابقة المصادر الخارجية الحالية
| المصدر | يصلح له | لا يثبت |
|---|---|---|
| VehiclesDB (نسخة 2026.11.12) | أسماء الماركات/الموديلات، الهوية المستقرة، المرادفات، أنواع المركبات، بلدان الدليل، سنوات Lifecycle عند توفرها | أجيال ومحركات دقيقة، كود المحرك، كود علبة السرعة، ECU، أكواد DTC |
| gor3a/vehicle-makes-models (v1.0.3) | الماركات والموديلات والأجيال وسنواتها ومواصفات المحرك ونوع ناقل الحركة حين يتوفر | الكود المصنعي الموحّد للمحرك/علبة السرعة، ECU، أكواد DTC، الشمول الكامل |
| Delphi diagnostic.sdf و dtc.acz | **مرشحان للفحص فقط** بعد الحصول على الملفات الأصلية، ومعرفة بنية البيانات وحقوق الاستخدام | لا تفترض محتواهما قبل قراءة فعليّة |

**ترخيص VehiclesDB:** ملفات GitHub المفتوحة CC BY 4.0 مع الإشارة للمصدر وجميع إشعارات الجهات الأصلية.  
**ترخيص gor3a:** بيانات ODbL 1.0، يلزم تقييم شروط قاعدة مشتقة وحقوق مصدر autoevolution.  
**ملفات Delphi:** تتطلب صلاحية استخدام/مشاركة ولا تُنشر خامًا في GitHub العام.

## 5 — خطوات اعتماد بيانات كل سيارة
1. توحيد الماركة والموديل والمرادفات والهوية الخارجية وإضافة provenance.
2. ربط الجيل والسنوات والسوق مع إبقاء نطاقات التسجيل والإنتاج منفصلة.
3. جمع نسخة المحرك/علبة السرعة برقم OEM إن توفر، وإلا `null`.
4. مقارنة المركبة بالمكتبة الحالية للتأكد من الهوية ومنع التكرار والتعارض.
5. ربط DTC مع ECU والمحرك/ناقل الحركة **فقط** بدليل انطباق؛ حالات الالتباس تُؤجل للمراجعة.
6. اختبارات القبول: حقول صالحة، روابط المصدر، فحص التكرار، تحليل النواقص، توافق schema الحالي، عدم تعديل وسائط/بيانات مصدرية.
7. حفظ نتائج مراجعة في فرع مستقل مع Commit وPR؛ لا دمج في main أو إصدار تحديث دون مراجعة وموافقة.

## آخر نقطة استئناف
مطلوب تدقيق النسخ المرخصة الفعلية للمصدرين، إحصاء تغطية **كل حقل** ونسبة `null` والاختلافات، ثم اختبار ربط تجريبي مع مكتبة DTC NEXIS دون نشر. لا سجلات بيانات/أكواد أضيفت بسبب هذه الوثيقة.

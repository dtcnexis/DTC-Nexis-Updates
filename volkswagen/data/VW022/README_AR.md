# Volkswagen VW022 — قناة DTC NEXIS الرسمية

هذه البيانات **للمراجعة والاختبار فقط**، وليست تحديثًا آليًا صالحًا للتثبيت.

## طريقة الرفع المعتمدة لباقي الماركات

1. تحضير JSON موحّد مع معرفات أصلية ومراجع المصدر وحالة التحقق، بلا بيانات ورشة أو VIN أو صور مملوكة للغير.
2. تشغيل `make_catalog_export.py` لتحويل البيانات إلى أجزاء JSON محدودة الحجم، واستخراج `manifest.json` يحتوي SHA-256 والعدد المتوقع لكل قسم.
3. فحص كل جزء محليًا بواسطة `verify_staging_chunks.py`، بما فيه الأعداد والبصمات وعدم وجود تكرار داخل القسم.
4. رفع الملفات النصية باستخدام GitHub Contents/Git Tree API إلى **المستودع الرسمي نفسه** `dtcnexis/DTC-Nexis-Updates`؛ لا قنوات تحديث إضافية.
5. تجميع كل أجزاء الدفعة في شجرة Git واحدة، ثم إنشاء commit وتحديث `main` بعملية fast-forward واحدة. إن فشل إعداد أي جزء، لا تُفعَّل نسخة غير مكتملة.
6. إعادة قراءة `manifest.json` والملفات من GitHub ومقارنتها بالبصمات، وتسجيل commit في تقرير الرفع.
7. **لا تغيير** للملفات `update-feed.json` أو `pending-update-feed.json` أو مفتاح التحقق أو ملفات تثبيت Windows. كل ذلك يتطلب حزمة متوافقة وتوقيع المالك واختبار جهازه وموافقة صريحة على التفعيل.

## الحدود الفنية الحالية

- عدد السجلات في المصدر: **1699**، لا يعني ذلك 1699 سيارة مؤكدة.
- **644** كود VAG قديم مرشح غير مثبت لكل محرك أو VIN.
- لم يتم تضمين صور أو مخططات OEM، ولا يمكن إعلانها متاحة داخل التطبيق حتى تثبت الرخصة والتطابق.
- نجاح نقل البيانات إلى GitHub **لا يثبت** أن زر تحديث RC3.8.2 سيدمجها.
- هذه الملفات تُحفظ على المستودع العام بعد فلترة الحقول الشخصية المعروفة؛ لا تضع في هذا المجلد مفاتيح خاصة أو سجلات زبائن أو سجلات ورشة.

## اختبار التحديث لاحقًا

بعد تجهيز محول الاستيراد للنسخة المثبّتة وتوقيع الحزمة بالمفتاح الموجود والتحقق من بيانات الورشة: نجري أول تجربة **خاصة على جهاز المالك** دون المساس بسجلاته. بعدها فقط يتم تفعيل تحديث معتمد بالقناة الواحدة.

### أمر قابل لإعادة الاستخدام لأي ماركة

```bash
python volkswagen/tools/make_catalog_export.py /path/to/MAKE_master.json /tmp/make-staging "MAKE" "REVIEW01"
python volkswagen/tools/verify_staging_chunks.py /tmp/make-staging
```

بعد التحقق، تُرفع ملفات JSON الناتجة في مجلد الماركة على **نفس المستودع** وفي التزام واحد، ثم يُقارن SHA-256 مع `manifest.json`.
**ملاحظة نقل مهمة:** قارئ الملفات النصية في أداة النقل قد يحذف `\n` في آخر الملف؛ يجب إضافته عند إنشاء Blob على GitHub إذا كان موجودًا في الأصل، وإلا ستفشل بصمات manifest رغم سلامة JSON. لا تعتمد نجاح رفع ملف وحده قبل مقارنة SHA لجميع الأجزاء.
